## Product

Tokenshelf is a library of original design systems for coding agents. It helps people avoid the same generic AI-made UI.

- Browse the daily pick, Hot, and New. Open a system and copy it for an agent.
- Submit by giving an agent a short-lived capability link. The agent edits a structured DesignSystemDocument draft; the user reviews and publishes it.
- Structured JSON is canonical. DESIGN.md and RendererIR are deterministic derived artifacts.
- Live previews, community submissions, and the daily competition are the main difference from other DESIGN.md catalogs.
- The full product brief and wireframes are in `design/index.html`.

## Wasp

This project uses the Wasp framework.

### Docs

- Find docs via the index at https://wasp.sh/llms.txt
- Pick the docs map matching the Wasp version in `main.wasp.ts`.
- Prefer raw Markdown URLs from the docs map over guessing `wasp.sh/docs` URLs.
- If this file conflicts with versioned Wasp docs, trust the docs and tell the user this file may be stale.

### Wasp TypeScript Spec

- `main.wasp.ts` contains the Wasp version and the Wasp app specification.
- When it references app components/functions, import them from `src/` with `with { type: "ref" }`.
- `route(name, ...)` and `crud(name, ...)` take an explicit name.
- Other constructors take no name argument; the declaration's name is the imported identifier. For example, `job(sendReminder, { ... })` declares a job named `sendReminder`.
- `@wasp.sh/spec` is generated by Wasp, don't install it from npm.

### Verification

- Do not run `tsc` directly for validation.

### Database migrations

- Create migrations only with the Wasp CLI. Never create or edit migration files manually.
- Ask the user before generating or applying migrations or resetting the database.
